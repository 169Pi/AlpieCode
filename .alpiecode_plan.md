# Logging Module Refactor - Implementation Plan

## Overview
Add a comprehensive logging module to the AlpieCode project following Python best practices, integrating with the existing Rich terminal output infrastructure.

## Current State Analysis
- **No logging exists**: Search for `import logging` returned 0 matches
- **Rich dependency**: The project already uses `rich>=13.0` for terminal output
- **10 core modules**: `cli.py`, `agent.py`, `config.py`, `tools.py`, `memory.py`, `guardian.py`, `compaction.py`, `__init__.py`
- **Console output**: Currently uses Rich Console with fallback to plain print

## Deliverables

### 1. New File: `src/codeagent/logging.py`
Create a comprehensive logging module with:
- **LoggerFactory**: Central logger instance with configurable settings
- **Log levels**: DEBUG, INFO, WARNING, ERROR, CRITICAL
- **Console handler**: Integrates with Rich for colored output
- **File handler**: Optional file logging capability
- **Context managers**: For scoped logging (e.g., `with logger.debug_context(...)`)
- **Thread safety**: Proper locking for concurrent access
- **Configurable**: Support for log level and output format via config

### 2. Updated File: `src/codeagent/__init__.py`
- Export `Logger`, `get_logger`, `setup_logging` functions
- Add `__version__` to align with pyproject.toml (currently 0.1.0, should be 0.2.0)

### 3. Updated File: `pyproject.toml`
- Add `python-json-logger` or similar for JSON formatting (optional)
- Update version to 0.2.0

### 4. Updated Files - Integrate Logging
Add logging calls to key modules:
- **`cli.py`**: Log CLI commands, errors, and completion status
- **`agent.py`**: Log agent turns, API calls, checkpoints
- **`config.py`**: Log config loading, validation errors
- **`tools.py`**: Log tool execution (with appropriate levels)
- **`guardian.py`**: Log security decisions (risk levels)
- **`memory.py`**: Log memory save/load operations

### 5. New File: `test_logging.py`
Comprehensive tests for the logging module:
- Test logger creation and configuration
- Test all log levels (DEBUG, INFO, WARNING, ERROR, CRITICAL)
- Test console handler output
- Test file handler output

## Design Decisions

1. **Use Python's standard logging module**: Proven, well-tested, and familiar to developers
2. **Integrate with Rich**: Leverage existing dependency for colored console output
3. **Modular design**: Logger is importable and reusable across all modules
4. **Config-driven**: Log level and handlers configured via `setup_logging()`
5. **Graceful fallback**: If Rich is unavailable, fall back to plain text (already handled in existing code)
